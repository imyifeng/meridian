# AI 接入：服务端代理、function calling 与按任务分段上下文

智能体的大模型调用全部由服务端代理（OpenAI-compatible `/chat/completions`，最终文本回复走 SSE 流式），API Key 只存实例数据库、永不下发客户端。接入配置即词汇表中的 AI Settings：实例级唯一一份（Base URL、模型名、API Key、启用开关），仅管理员经 Web Console 修改，可一键测试连通；配置生效后所有登录用户可用，不设逐用户授权。工具化采用 OpenAI function calling 而非字面实现 MCP 服务器：服务端自建工具执行循环，用户感知无差别、复杂度低得多；未来确有外部系统接入需求时再补 MCP 端点。

工具集与安全边界：创建走 Draft 草稿卡片——模型只能调 propose_draft 生成预览，用户点"没问题"后由客户端调用既有备忘录创建接口落库，模型永远不直接创建；检索复用现有 FTS5 全文搜索（search_memos 返回紧凑结果列表，get_memo 取单条全文），绝不把备忘录批量塞进模型上下文；修改与删除由模型直接调工具执行并在对话内回显，误删靠回收站兜底（永不自动清空）；分类只能从既有分类中选择，标签永不由模型生成或修改。时间歧义追问策略内建在服务端系统提示词、不可由管理员自定义：缺具体钟点（"明天下午开会"）要追问；钟点歧义（"后天9点"）要追问上下午；凌晨说"明天"要确认日期归属；完全没有时间（"帮我记住XX"）不追问——提醒是可选项。客户端每条消息附带本地时间与时区，相对时间据此解析。

上下文按任务分段：一次"任务"=一条用户消息 + 为补全它而发生的追问轮次 + 工具往返；模型每次回复以 awaiting_input 标志声明任务是否仍在等待用户输入（追问中、草稿卡片待处理为是）。任务结束后其消息不再进入后续请求的模型上下文；聊天记录仅作为展示持久化，用户可整段删除。接受的代价：检索答复之后无法用"第二条"这类指代继续操作，模型会要求重新指明——换来的是 token 成本恒定、与会话总长度无关，因为信息的主存储是备忘录本身（随时可检索），聊天只是操作通道。
